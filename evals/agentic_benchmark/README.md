# Agentic RAG 真实模型评测

本套评测比较当前生产代码的普通知识库 RAG 与知识库 Agent，不替换模型响应。
资料是人工定义的 Atlas/Nebula 合成运维文档，不是本项目实际产品规格，也不是公开通用基准。

## 固定资料与问题

- 12 份 Markdown，当前分块策略下为 87 块（分块大小 500 字符、最大重叠 100）。
- 30 道单轮题：直接题 5、综合题 8、版本题 6、上下文题 5、不可回答题 4、澄清题 2。
- 2 个各 8 轮的会话：操作系统纠正与版本纠正。第 2 轮的实际条件在最后 5 轮之外，
  中间插入明确询问其他话题的对话，最后返回实际场景。
- 文档、题目、预设答案要点和原文依据均在正式运行前固定，运行保存内容哈希。
- 两题联调用于检查记录与评分规则：发现超时题有一个未明确问出的评分要点，正式版在题干中补问；
  移除 Windows 支持题中不必要的额外解释要求。联调结果不混入正式结果，正式运行不再修改题集。

## 运行

项目根目录 PowerShell：

```powershell
.\.venv\Scripts\python.exe evals/run_agentic_benchmark.py --workers 3
```

这会真实调用项目 `.env` 配置的 DeepSeek、百炼 Embedding 和 Reranker，产生实际费用。
密钥不会写入评测结果。SQLite、文件上传目录和 Chroma 均使用隔离存储；只读核对正式数据库与
上传文件哈希，输出 `official_data_unchanged`。结果目录包含：

- `metadata.json`：模型、配置、代码/数据哈希、Git 状态、正式数据前后哈希。
- `chunks.json`：实际分块、字符位置、临时文档标识。
- `setup_calls.json`：资料入库的真实模型 usage。
- `answers.jsonl`：60 次单轮对照的答案、来源、工具调用、真实供应商 usage、耗时、自动评分。
- `retrieval.jsonl`：4 种检索配置各 30 题的原始结果，共 120 次检索。
- `memory.jsonl`：2 场景 × 2 方法 × 8 轮，共 32 次多轮问答；最后一轮评分。
- `session_summaries.json`：真实持久化的 Agent 摘要，核对是否触发压缩。
- `summary.json`：指标与分组计数，运行期间增量更新。

运行结束后可生成来源核对与报告（不额外请求模型）：

```powershell
.\.venv\Scripts\python.exe evals/audit_agentic_benchmark.py evals/results/<本次结果目录>
.\.venv\Scripts\python.exe evals/report_agentic_benchmark.py evals/results/<本次结果目录>
```

`audit.json` 核对引用编号、原文及来源身份；`context_evidence.jsonl` 使用 Agent 在预算筛选后
实际纳入上下文的片段计算依据覆盖。原始 `answers.jsonl` 中的 `retrieval_metrics` 来自观测到的
工具召回结果，可能含后续被预算省略的片段，两者应区分。核对身份成功不等于语义引用支持。

可用 `--limit 2 --skip-memory --skip-ablation --workers 2` 做小规模链路检查。
每次运行新建结果目录，不将失败重新跑出的成功响应覆盖原失败。
已有题集不会被运行器重写；主动执行 `agentic_dataset.py` 才会重建资料。

## 对照约束

普通 RAG 使用生产 `/knowledge-bases/{id}/ask-rag`，Hybrid、Top-K=5、候选池30并启用重排。
Agent 使用生产 `/knowledge-bases/{id}/agent`，默认同样 Hybrid/Top-K=5/重排，但模型可以选择
查询、检索模式、Top-K、文档范围与相邻块工具；执行次数、时间、上下文等均沿用项目配置。
这是系统整体的比较，包括两者不同提示词和 Agent 的相似度过滤，不能把差异全部归因于工具循环。
两条路线均使用同一批已索引资料，不为每题重复入库。

消融包括 BM25+重排、Dense+重排、Hybrid不重排、Hybrid+重排。全部固定候选池30与Top-K=5，
因此 Hybrid 开关重排的对照没有同时改变候选池。该阶段只测检索，不生成答案。
每组结束后才改变配置，组内只并发独立请求。

多轮普通 RAG 使用生产 `/ask-rag/chat`（最近5轮、问题改写），Agent 使用实际会话摘要实现。
每个场景/方法创建独立会话，顺序执行8轮，各自保留模型生成历史。因而比较真实多轮系统行为，
不是仅切换摘要开关、其余消息完全一致的纯摘要消融。第8轮才计入目标质量分数。

## 指标与评分

1. **依据覆盖**：按预设证据在固定文档中的字符区间，检查检索分块覆盖区间的并集。
   支持证据跨块，不把只命中其中一个字算作完整命中。报告任何依据命中与全部依据覆盖，
   拒答题的否定说明不计入可回答题检索覆盖分母。
2. **任务通过**：预设要点全部匹配、行为正确、没有评审发现的无依据事实。
3. **严格通过**：在任务通过基础上，实际引用也支持相应结论且关键事实有引用。
4. **评分主体**：同一 DeepSeek 模型，以固定规则和 temperature=0 对答案进行自动评审；
   调用不提供对照方法名。保留原始评分JSON、扣分理由与评分调用usage。没有独立人工复核者，
   不宣称此计数为无误的真实准确率。编号合法性由生产接口检查，语义支持度由自动评审判断。
5. **失败处理**：请求失败和评审失败均保留并计入总题数，通过数不排除失败；
   要点平均覆盖另注明只在成功评分样本上计算。
6. **耗时**：生产API链路的墙钟耗时，不包含评分和资料入库；分别报告全体尝试与成功请求
   的P50/P95。使用TestClient，不代表外网、浏览器、SSE首段耗时或并发容量。
7. **成本**：保存回答、问题改写、摘要、Embedding、重排和评审的实际供应商usage；
   评审与入库成本单列，不把Agent内部字节上界预算当token实测。没有根据未核对的价格换算金额。

当前每个样本只正式跑一遍，属于小规模探索；没有覆盖扫描型PDF/OCR、真实用户数据、
高并发、跨环境性能或多次运行置信区间。结果适合定位失败和描述本固定测试集的表现。

