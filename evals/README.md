# 30 题 RAG 基线

`questions.jsonl` 共 30 道人工编写的题目，保留最初的 5 题：10 道直接题、8 道综合题（跨段或组合多个事实）、6 道同义表达题、6 道不可回答题。每道可回答题都预先写好答案要点和逐字原文依据，不根据模型输出修改标准。

`documents/pilot.md` 是项目功能说明的合成资料；`documents/odysseus.md` 是上传文件 `uploads/11111.md` 的固定副本，保留原文及其噪声。后者只按文档内容评分，不做神话史实的外部核验。这仍然是两份较短资料的初版基线，不能代表全部真实文档或长文档检索效果。`expand_questions.py` 保存题目的人工定义，运行会重建 30 题及文档副本；正式固定基线后请不要随意改变文档和题目。

在项目根目录运行（会产生真实模型调用费用）：

```powershell
.\.venv\Scripts\python.exe evals/run_baseline.py --mode hybrid --top-k 5
```

也可以分别设置 `--mode bm25` 和 `--mode dense`，使用相同题目进行比较。需要现有 `.env` 中的回答模型配置；dense/hybrid 还需要 Embedding 配置。不需要启动 HTTP 服务，脚本通过 FastAPI TestClient 调用真实接口，模型 API 不模拟。使用隔离 SQLite 和真实内存 Chroma，不修改正式数据库或上传文件。

每次结果存放在 `results/<UTC时间>-<模式>/`：

- `metadata.json`：代码提交、工作区状态、代码/题目/文档哈希、模型及检索配置。
- `chunks.json`：本次实际分块及偏移；临时 document_id 不作为题目的固定标识。
- `results.jsonl`：逐题保存检索和回答的 HTTP 状态、耗时、完整原始响应及待人工填写的 review 字段。即使某题失败也继续保存后续结果。
- `summary.json`：运行成功数和原文依据匹配统计，不自动宣称回答正确率。
- `review.json`：如有，人工对照题目和原文的复核结果，与原始响应分开保存。

`evidence_quote_coverage` 是忽略空白后的依据全文包含率；若一句依据被切到多个块中，该指标可能漏判。它不是语义相关性指标，资料外题返回候选也不代表检索失败。回答正确性、引用支持度、拒答由人工复核。

检索与回答分开调用；ask-rag 内部会再次检索，因此这两次检索可能不同，耗时不能相加当作一次用户请求耗时。脚本测单轮非流式链路，不测多轮改写、网络浏览器或首段耗时。

首次试跑为 hybrid、Top-K=5。5 道检索及回答均返回 200，可回答题 3/3 完整匹配依据，2 道资料不足题未编造所问数值。人工复核见对应 review.json；样本很小，不能推广为正式正确率。首次使用临时持久化 Chroma，结束清理时遇到 Windows 文件占用；原始结果完整，summary 根据保存记录恢复，后续脚本改用内存 Chroma。

30 题运行见 `results/20261006T080420Z-hybrid/`。真实 hybrid、Top-K=5 的检索和回答均为 30/30 成功，可回答题 24/24 完整匹配预设依据。助手逐题复核：22 道完全正确、2 道部分正确（q021 漏自然边界优先；q025 补充了原文没有的“忘忧果”），6 道不可回答题均正确拒答。q025 的引用只能支持核心动作，不能支持额外食物名称。没有独立复核者，暂未跑 BM25/dense 对比；两份文档只有 6 和 3 个分块，检索难度较低。
