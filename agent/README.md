# Agent 的会话上下文

知识库 Agent 接口携带 `session_id` 时，会把数据库中的旧会话摘要、最近原始问答、当前问题和本轮工具结果组装成上下文。单文档 RAG 和传统知识库 RAG 接口仍使用原来的历史策略。

## 执行顺序

1. `runner.py` 创建本轮状态、总时间上限和上下文预算。
2. `memory.py` 校验会话归属，读取完整原始历史和已保存的摘要。
3. 默认保留最近 5 轮；如果原始问答超过历史预算，则把更多完整旧轮次纳入摘要。
4. 用现有 DeepSeek 模型增量更新结构化摘要。只输入用户原话，提取背景、目标、约束、话题和问题；不把历史模型答案变成文档事实。
5. 校验 JSON、原话出处、会话内轮次 ID 和摘要大小后，提交摘要及覆盖游标。来源发生变化时重建；版本检查阻止并发迟到结果覆盖新摘要。
6. `context.py` 组装消息并在每次模型调用前检查预算。最近对话和当前问题的新条件优先于旧摘要。
7. 工具结果超过预算时，从低优先级结果末尾移除完整片段或目录项。只有实际纳入上下文的片段才注册引用，不截断正文、不拆开工具调用与返回的协议对。必要时结束工具阶段，使用已有证据生成最终答案。

摘要以 `(knowledge_base_id, session_id)` 隔离，存于 SQLite 的 `agent_session_summaries` 表。表记录结构化内容、`covered_turn_id`、原始来源哈希、修订号和更新时间。`init_db()` 自动新增表，不需要手工迁移。原始问答仍完整保留在 `knowledge_base_turns`，历史页面不会只剩摘要。

摘要在下一轮请求开始时同步更新；只有出现未压缩的旧轮次才额外调用模型，长会话首次加载可能需要多个小批次。这是会话内记忆，不是跨会话个人长期记忆，也没有引入子 Agent 或新框架。摘要仍可能丢失细节，文档事实必须通过本轮工具重新取得。

## 配置

在项目 `.env` 中可选配置以下变量，无需新增 API Key：

```dotenv
AGENT_RECENT_TURNS=5
AGENT_CONTEXT_TOKENS=24000
AGENT_HISTORY_TOKENS=6000
AGENT_SUMMARY_TOKENS=4000
```

这些值使用**保守的 UTF-8 字节上界估算**，不是供应商 tokenizer 的精确 token 数；汉字约占 3 个估算单位。总预算包含消息、工具定义和 2000 token 输出预留。摘要模型调用也检查总预算。历史和摘要上限是子预算，调小总预算时应同步调小这两项并给系统提示、工具定义及检索结果留空间。

摘要失败不会推进覆盖游标或删除历史；该轮返回错误，可以重试。单轮原始问答过长、固定提示或元数据本身超过预算时明确报错，不静默截断。取消和超时也适用于摘要阶段。已成功提交的旧历史摘要可以保留，但失败的当前问答不会保存。

Agent 响应新增 `context_usage`，包含近期轮数、摘要覆盖游标、摘要条目数、更新批次数、总预算、请求峰值估算和因预算省略的工具项数。它供接口调试使用，历史接口仍返回原始问答与来源。

## 验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

`tests/test_agent_memory.py` 验证摘要增量更新、条件纠正、来源和会话隔离、失败不推进游标、删除后失效、并发版本校验、整轮历史预算、真实引用编号及工具消息配对。
