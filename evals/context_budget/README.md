# 检索后上下文超预算专项

该专项验证两项改动：重复分块正文在工具消息中只保留一次；工具历史装不下、但完整证据上下文装得下时，直接进入最终回答而不是先删除新证据。

## 必须实际触发的条件

预算固定为项目默认 **24000** 个 UTF-8 字节上界估算单位，包含2000输出预留。明确要求：

```text
完整检索结果加入前的上下文估算 <= 24000
完整检索结果加入后的上下文估算 > 24000
```

不会通过降低预算或把用户问题重复到超长来代替此条件。原始结果可以超预算，但所有实际发给模型的请求必须通过预算检查。

## 对照

- **before**：修复前的尾部删减算法，不压缩重复工具正文。
- **after**：当前生产 `fit_tool_result()` 与 `compact_tool_messages()`。
- 提示词、工具定义、上下文预算、分块、重排和 MMR 配置保持一致。旧策略的代码保存在 `evals/context_budget_baseline.py`，沿用当前提示词和最终证据格式，避免同时更换提示词。

## 三层验证

1. **历史真实检索轨迹回放**：读取2026-10-13 Agent评测中8道出现省略的题，使用当时保存的原始工具结果，对两个策略做成对回放。不重新调用检索或生成历史答案。回放恢复工具名、参数和原始结果，不恢复当时助手说明文字、并行调用批次和校验纠正消息，因此省略数量不要求与历史报告完全相同。
2. **本次真实固定检索计划**：三个预先规定的计划覆盖重复备份检索、互补上线检索、相邻块回滚检查。真实执行查询Embedding、重排和工具检索，两组消费相同结果，再分别调用真实模型生成最终答案。计划由评测控制，不冒充自主Agent。
3. **真实自主Agent**：使用生产Agent独立运行a006、a009、a013、a019四题，每题前后各一次。模型自行选择工具和检索内容，属于整体行为比较，轨迹不保证相同。

检索库在独立SQLite与内存Chroma恢复，只使用原Atlas/Nebula 12份资料。向量复用先前真实Embedding生成的快照，不使用模拟向量；本次查询Embedding和重排仍真实调用。原始工具结果及模型请求保存在结果中，密钥不写入输出。

## 运行

```powershell
.\.venv\Scripts\python.exe evals/run_context_budget_benchmark.py --replay-only
.\.venv\Scripts\python.exe evals/run_context_budget_benchmark.py --direct --workers 2
```

`--direct`仅影响本次评测进程的连接，不更改系统代理。完整运行产生真实模型调用费用，每次输出新目录，不覆盖失败记录。

结果保存在 `evals/results/<UTC时间>-context-budget-v1/`，含逐次预算估算、是否真正跨过预算、保留/省略数量、去重次数、收尾动作、实际模型请求、原始答案、评分及代码快照。

所有数值是项目预算估算，不是供应商tokenizer的精确值，也不代表触发了模型服务器的硬上下文上限。单次同模型自动评分只作辅助，主要验收条件是确实触发检索后超预算，并且保留证据、引用身份和调用协议正确，实际请求未超预算。

首轮完整结果见 [报告](../results/20261020T062342Z-context-budget-v1/REPORT.md)、[目标触发证据与复核](../results/20261020T062342Z-context-budget-v1/REVIEW_NOTES.md)。实际自主Agent4题中，旧策略省略36项、新策略1项；固定检索计划3题均在加入结果后超预算，新策略均省略0项。实际32次模型请求均在预算内。

可离线检查：

```powershell

```
