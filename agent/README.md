# Agent 的会话上下文

知识库 Agent 接口携带 `session_id` 时，会把数据库中的旧会话摘要、最近原始问答、当前问题和本轮工具结果组装成上下文。单文档 RAG 和传统知识库 RAG 接口仍使用原来的历史策略。

## 执行顺序

1. `runner.py` 创建本轮状态、总时间上限和上下文预算。
2. `memory.py` 校验会话归属，读取完整原始历史和已保存的摘要。
3. 默认保留最近 5 轮；如果原始问答超过历史预算，则把更多完整旧轮次纳入摘要。
4. 用现有 DeepSeek 模型增量更新结构化摘要。只输入用户原话，提取背景、目标、约束、话题和问题；不把历史模型答案变成文档事实。
5. 校验 JSON、原话出处、会话内轮次 ID 和摘要大小后，提交摘要及覆盖游标。来源发生变化时重建；版本检查阻止并发迟到结果覆盖新摘要。
6. `context.py` 组装消息并在每次模型调用前检查预算。最近对话和当前问题的新条件优先于旧摘要。
7. 工具结果到达后，先将模型消息中相同分块、相同引用编号的重复正文替换为 `content_reference=true`，首次出现的完整正文保留。完整结果仍保存在工具执行记录，引用编号与来源不变。
8. 去重后的运行历史与完整最终证据都装得下时继续；只有工具历史装不下但完整最终证据装得下时，保留全部新结果，结束工具阶段并生成最终回答。仅当最终证据本身也装不下时，才从本次结果末尾移除完整片段或目录项。不截断正文，不拆开调用与返回的协议对。

摘要以 `(knowledge_base_id, session_id)` 隔离，存于 MySQL 的 `agent_session_summaries` 表。表记录结构化内容、`covered_turn_id`、原始来源哈希、修订号和更新时间。`init_db()` 自动创建不存在的表；旧 SQLite 数据迁移见 [MySQL 使用说明](../docs/mysql.md)。原始问答仍完整保留在 `knowledge_base_turns`，历史页面不会只剩摘要。

摘要在下一轮请求开始时同步更新；只有出现未压缩的旧轮次才额外调用模型，长会话首次加载可能需要多个小批次。这是会话内记忆，不是跨会话个人长期记忆，也没有引入子 Agent 或新框架。摘要仍可能丢失细节，文档事实必须通过本轮工具重新取得。

## SSE 流式问答

知识库聊天调用 `POST /knowledge-bases/{base_id}/agent/stream`，请求仍是 `AgentRequest`（`question` 和可选 `session_id`）。`run_document_agent(..., on_event=callback)` 使用 SDK 的模型流式接口累积工具调用参数，`streaming.py` 解码不完整 JSON 和跨片段转义，只把 `answer` 字段作为增量预览；不传回调时保留原来的非流式执行方式。

SSE 依次按实际执行过程发送 `meta`、`status`、`tool_start`、`tool_call` 和 `delta`。校验失败时用 `reset` 清除预览，在既有预算内纠正；目录和依据不足的文案直接使用后端校验结果。引用规范化和范围提示也以校验结果为准。`done` 包含完整的正文、引用、工具记录和保存 ID，只在保存成功后发出。失败发送 `error`，不会把失败的回答存入历史。

接口在独立工作线程中通过统一连接入口持有 MySQL 连接，通过有界队列把事件传给响应生成器，等待资料期间每 15 秒发送 SSE 注释心跳。断开连接设置取消标记，模型每个流式事件及工具执行前后检查取消和总时间预算；取消会关闭模型流，工具和摘要外部调用在检查点结束。未完成轮次不会保存，已成功更新的旧会话摘要可保留。

## 配置

在项目 `.env` 中可选配置以下变量，无需新增 API Key：

```dotenv
AGENT_RECENT_TURNS=5
AGENT_CONTEXT_TOKENS=24000
AGENT_HISTORY_TOKENS=6000
AGENT_SUMMARY_TOKENS=4000
```

这些值使用**保守的 UTF-8 字节上界估算**，不是供应商 tokenizer 的精确 token 数；汉字约占 3 个估算单位。总预算包含消息、工具定义和 2000 token 输出预留。摘要模型调用也检查总预算。历史和摘要上限是子预算，调小总预算时应同步调小这两项并给系统提示、工具定义及检索结果留空间。

摘要失败不会推进覆盖游标或删除历史；该轮返回错误，可以重试。单轮原始问答过长、固定提示或元数据本身超过预算时明确报错，不静默截断。取消和超时也适用于摘要阶段。已成功提交的旧历史摘要可以保留，但失败的当前问答不会保存。

Agent 响应的 `context_usage` 包含近期轮数、摘要覆盖游标、摘要条目数、更新批次数、总预算、请求峰值估算和因预算省略的工具项数。新增 `deduplicated_tool_items`（重复正文压缩次数）、`finalized_due_to_context`（因上下文收尾）及 `context_decisions`（逐次完整结果加入前后的预算决策）。决策记录保存原始工具历史、去重后历史、完整最终证据的估算大小，以及删减和收尾动作；原始结果超过预算不等于实际向模型发送了超限请求。它们供接口调试使用，历史接口仍返回原始问答与来源。

## 验证

```powershell
$env:RERANK_ENABLED = 'false'
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

`tests/test_agent_memory.py` 验证摘要增量更新、条件纠正、来源和会话隔离、失败不推进游标、删除后失效、并发版本校验、整轮历史预算、真实引用编号及工具消息配对。

`tests/test_agent_stream.py` 使用真实 SDK 流式累积器和模拟 HTTP 模型响应，验证工具参数跨片段拼接、回答在模型结束前逐段到达、JSON 转义、引用纠正、截断、取消，以及 SSE 保存成功/失败和会话隔离。上述命令关闭外部重排以隔离网络和排序变化；重排自身的测试会单独启用并模拟响应。
