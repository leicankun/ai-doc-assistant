# 检索核心质量与阶段损失

后续优先查看四项：**必要证据覆盖率、完整覆盖题数、MRR@5、阶段证据损失**。回答自动评分仍作为辅助，不能代替检索指标。

已完成对之前真实分块评测 240 条检索轨迹的只读复算：[核心报告](../results/20261021T061728Z-retrieval-quality-v1/RETRIEVAL_QUALITY.md)。本次新增模型调用为 0，原始模型输出与题集没有改动。

## 六个观察点

| 观察点 | 用途 |
|---|---|
| 候选池（最多30） | 查必要依据是否已经召回 |
| 清理后的完整候选池 | 查标题过滤或精确去重是否误丢证据 |
| 清理后 RRF Top-5 | 不经过模型重排的同 K 基线 |
| Rerank Top-5 | 与同 K 基线比较模型排序得失 |
| MMR Top-5 | 查多样性筛选丢失或补回了什么 |
| 2500 字符预算后 | 查统一上下文容量下还剩多少必要依据 |

实际处理路径是候选池→清理后候选池→Rerank Top-5→MMR Top-5→预算结果。RRF Top-5 是同一候选池的对照选集，不是把它当作重排模型仅有的输入。

## 指标口径

- **证据覆盖**：每道可回答题命中的必要证据组数量除以该题必要组数量，再按题平均。一个组内有多个替代出处时，命中任意出处即可。重复命中不重复加分；同一文档内可用多个片段共同覆盖原文区间。
- **完整覆盖**：该题所有必要组均命中。报告题数及分母。
- **MRR@5**：统一看每个阶段的前5项，第一个完整覆盖任意必要组的前缀排名取倒数，再按题平均；找不到计0。候选池覆盖看全部最多30项，但其MRR也只看前5项。不把候选池的MRR@30与最终MRR@5混在同一列。
- **阶段损失**：上一选集有、下一选集没有的必要组。另报补回组数、有损失的题数、完整变不完整题数。损失率分母为上一步已命中的证据组，与按题平均覆盖率是不同口径。
- 30→5本身有容量筛选，不能把该步所有缺失都说成模型排错。因此额外比较清理后RRF Top-5和Rerank Top-5，分别记录丢失与补回，避免净差掩盖证据替换。
- 拒答、澄清题不进入证据覆盖或MRR分母，不因为它们召回内容就判错。请求失败保留在题数中、证据命中按0计，错误另列；此前没有命中时损失率记为空值。

预算部分沿用分块评测的2500原文字符诊断：按MMR最终排名保留可装入的完整块，不截断、不补Top-5以外的项。它不等于Agent的24000保守估算单位，也不构成新一次Agent真实超预算评测；实际Agent预算实验仍见 [上下文预算专项](../context_budget/README.md)。

## 当前结果如何解释

原始短章节 test 集共40题，其中32道可回答：

| 阶段 | 平均证据覆盖 | 完整覆盖 | MRR@5 |
|---|---:|---:|---:|
| 候选池 | 98.96% | 31/32 | 0.8578 |
| 清理后RRF Top-5 | 95.83% | 29/32 | 0.9281 |
| Rerank Top-5 | 85.42% | 23/32 | 0.8292 |
| MMR Top-5 | 79.69% | 22/32 | 0.8073 |
| 2500字符预算后 | 79.69% | 22/32 | 0.8073 |

同K比较中，重排丢失8组、补回2组；MMR进一步丢失3组、未补回必要组；短块在2500字符筛选时未继续丢证据。这个固定合成样本中，应优先排查重排/选择，不能据此直接自动关闭生产功能或宣称普遍退化。

长章节 `500＋100` 在同K重排比较中丢失1组、补回1组：尽管总命中组数没变，丢失和补回发生在不同题目，必须分别报告。长章节 `800＋160` 的MMR Top-5覆盖完整，但2500字符后丢失4组、涉及3题。报告按语料分组，不跨结构归因。

标注原文区间覆盖是确定性代理指标，可能没有穷尽其他有效证据。比如此前r045已有可支持所问维度的版本对照原文，固定gold仍要求另一整句，因此不能将区间覆盖比例直接称为答案准确率。案例说明见原始运行的 REVIEW_NOTES。

`run_retrieval_benchmark.py` 和 `run_chunking_benchmark.py` 以后的真实运行会在结束时自动额外生成：

- `RETRIEVAL_QUALITY.md`：核心指标与阶段损失主报告。
- `retrieval_quality.json`：各语料组的dev/test/all汇总。
- `retrieval_quality.jsonl`：逐题各阶段命中、块ID、丢失和补回。
- `retrieval_failure_cases.json`：最终缺失及中间阶段有损失的案例，含问题、必要证据和各阶段块ID。

独立复算器额外保存源文件哈希、使用的清理代码哈希、分析代码快照和审计结果。清理代码与真实运行版本不一致时拒绝复算清理阶段；不把当前策略输出冒充历史轨迹。不会覆盖原运行报告，也不改原评分、生产参数或正式数据。
