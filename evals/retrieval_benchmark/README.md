# 60 题检索、去重与 MMR 专项

核心指标主口径见 [检索核心质量与阶段损失](../retrieval_quality/README.md)。运行结束会额外生成 `RETRIEVAL_QUALITY.md`，优先检查证据覆盖、完整覆盖、MRR@5及各阶段丢失/补回；原有回答评分作为辅助保留。

这是独立的新题集，不覆盖既有 30 题基线。所有运维规则均为助手预先定义的虚构资料，不是实际产品规格，也不是独立人工编写的公开基准。

## 固定数据

- 20 份 Markdown：保留原 Atlas/Nebula 的 12 份资料内容，新增 Orion/Aster 8 份资料。
- 163 个正文段落，生产分块策略使用 500 字符上限、最多 100 字符重叠；另有文档标题块。
- 60 题：直接事实 10、同义表达 10、综合/跨文档 10、重复干扰 10、版本/环境例外 8、资料不足 6、澄清 6。
- 20 道开发题只使用 Orion 事实；40 道验收题使用 Atlas/Nebula/Aster。相同事实的同义问法留在同一集合。
- 在任何模型调用前固定题干、答案要点、必要证据组、段落冗余组、20 道回答验证题及 MMR 权重 0.8。
- `manifest.json` 保存文档、题目和段落标注的哈希。运行器先校验哈希，生成器拒绝覆盖已固定的版本。README 不纳入数据哈希。

`questions.jsonl` 的 `evidence_groups` 是回答需要的证据组；每组的 `alternatives` 是可以互相替代的出处，命中一个即可。证据记录文档、段落和原文，运行时解析字符区间，避免绑定不稳定的数据库分块 ID。

`sections.jsonl` 预先定义段落区间及 `redundancy_group`。只有完整包含可互相替代的整个段落的块才共享冗余标记，跨版本或例外条件不会合并。未明确标成一组的语义重复可能漏计，指标不是全量语义重复率。

## 运行

```powershell
.\.venv\Scripts\python.exe evals/run_retrieval_benchmark.py --validate-only
.\.venv\Scripts\python.exe evals/run_retrieval_benchmark.py --workers 3
```

真实调用 Embedding、Rerank、回答和评审 API，会产生服务调用费用；使用独立临时 SQLite 与内存 Chroma，不写正式数据库、上传目录和正式向量库。运行前后核对正式数据库及上传文件哈希。

可用 `--limit 2 --skip-answers` 做独立的小规模联调。每次生成新的结果目录，不用后续成功覆盖原失败。运行器不重建或更改题集。

若环境代理到模型服务的 TLS 握手失败，可加 `--direct`，仅在评测进程内绕过环境代理，系统代理配置不变。结果 metadata 会记录连接模式。

## 四组对照

每题仅调用一次生产 `search_base()`，用评测专用适配跳过后处理，取得同一份 Hybrid/RRF 原始 Top-30 候选。初始候选池的内容和排序存入原始结果。

| 组别 | 最终选择过程 |
|---|---|
| A | 原始 RRF → Top-5 |
| B | 标题过滤、同文档正文精确去重 → Top-5 |
| C | 同样清理 → 真实模型重排 → Top-5 |
| D | 同样清理 → 同一次真实模型重排 → MMR → Top-5 |

C/D 共用对清理后全部候选的真实重排结果。这样两者差别只有选择算法，不包含两次模型调用的随机差异。MMR 仅读取隔离 Chroma 的已有向量，调用生产 `apply_mmr()`，不重新生成向量。

初始候选池均为 30，清理后不补召回，最终上限 5。MMR 权重固定 0.8，不使用验收结果调参。

## 指标

- **候选池与最终证据覆盖**：按必要证据组计算，组内允许替代出处；支持跨相邻块覆盖原文区间，不能跨文档拼接。
- **完整覆盖题数**：该题所有必要组都找到。资料不足和澄清题不进入证据覆盖分母。
- **MRR@5**：前五项的前缀第一次完整覆盖至少一组必要证据的倒数排名；全部未命中计 0。这里评价首组有效证据，不等于复杂问题已经答全。
- **冗余率**：明确标注的可替代段落中，多余返回次数除以全部返回数量；同时报告返回数量与纯标题块，避免空结果造成表面收益。
- **耗时**：共享召回、清理、共享模型重排与 MMR 的实测组件时间；报告组件之和 P50/P95，不冒充四条独立 HTTP 端到端请求耗时。
- **调用量**：记录实际供应商 usage，分开列出入库、检索、回答、评审；共享调用不重复计费统计，不使用未经核对的单价换算金额。

预先选定的 20 道验收题在四组上下文上分别调用生产 `answer_with_chunks()`，共 80 次回答。用相同模型、固定规则、temperature=0 盲评，分别记录答案要点、行为、无依据事实和已表达事实的引用支持；遗漏答案不混入引用错误。另用程序核对引用身份。

请求失败与评分失败都保留在总题数中。拒答、澄清只能由回答阶段评价，不能因为它们召回了片段就判错。

## 结果与限制

输出 `evals/results/<UTC时间>-retrieval-v1/`，包含 `REPORT.md`、`summary.json`、`retrieval.jsonl`、`answers.jsonl`、`calls.jsonl`、实际分块/向量，以及代码和数据快照。

单次试验、合成资料、同一助手编题与规则设计、同模型评审；没有独立人工评分，不作真实用户准确率承诺。此次不运行 Agent、多轮记忆或稳定性重复试验，也不测浏览器、SSE 首段、高并发及 OCR。

首轮完整结果见 [2026-10-20 报告](../results/20261020T052604Z-retrieval-v1/REPORT.md) 与 [案例及评分复核](../results/20261020T052604Z-retrieval-v1/REVIEW_NOTES.md)。正式验收平均证据覆盖率：A 91.67%、B 95.83%、C 85.42%、D 79.69%；该固定配置下 MMR 没有带来覆盖收益。
